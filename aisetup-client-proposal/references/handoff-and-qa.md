# PDF・Google Drive・案件管理の引継ぎ

## 顧客別作業フォルダ

顧客情報を含む成果物は、共有スキルフォルダへ保存しない。原則として次へ置く。

```text
03_顧客案件/YYYY-MM-DD_会社名_AIエージェント導入提案/
├── 01_提案ブリーフ.md
├── 02_見積承認記録.md
├── pages/
├── output/
│   └── 会社名_AIエージェント導入提案.pdf
└── qa/
    └── proposal-manifest.json
```

既存の顧客案件フォルダがある場合は新規重複を作らず、既存フォルダを使う。

## PDF作成

```bash
python3 scripts/build_proposal_pdf.py \
  --pages "/absolute/path/to/pages" \
  --output "/absolute/path/to/output/proposal.pdf" \
  --title "AIエージェント導入提案"
```

スキルが別の場所にある場合は、`SKILL.md` を基準にスクリプトの絶対パスを解決する。

## 内容QA

- 会社名と面談相手を取り違えていない
- 顧客発言、事実、営業仮説、未確認を混ぜていない
- 提案する1業務が全ページで一致する
- 現在フローと導入後フローがつながっている
- AIが担当する範囲と人間確認が一致する
- 対応範囲、対象外、顧客準備物が明確
- 見積金額、税区分、支払い、納期に承認記録がある
- 30日修正と月額プランを過大に説明していない
- 売上、工数削減、精度等を保証していない

## 画像・PDF QA

- PNG枚数とPDFページ数が一致する
- 連番に欠番・重複・逆順がない
- 全画像が16:9で同じ寸法
- 会社名、金額、日付、ページ番号に誤字がない
- ロゴが公式画像で、変形・偽ロゴがない
- 文字切れ、偽文字、見切れ、黒帯、意図しないトリミングがない
- PDFをPNGへ再レンダリングして全ページを原寸確認した
- PDFのAuthor、Creator、Subject、Keywordsに不要情報がない
- 公開するPNGやPDFに端末パス、プロンプト、顧客内部メモがない

## Drive保存

1. 顧客の既存Driveフォルダまたはユーザー指定フォルダを確認する。
2. 最終PDFだけをアップロードする。ブリーフ、見積承認記録、プロンプトは外部共有しない。
3. アップロード直後は制限付き共有を既定にする。
4. 人間の外部共有承認後だけ、必要な共有範囲へ変更する。
5. ファイルID、URL、共有権限、更新時刻を読み戻す。

同名ファイルがある場合は、既存承認済み資料を上書きしない。版付きで保存し、どちらを顧客へ渡すか人間が選ぶ。

## 案件管理

管理元: `AIセットアップ事業_営業導入管理_2026-08-28`

`02_案件管理` の既存列は次のとおり。

| 列 | 項目 |
|---|---|
| A | 会社名 |
| B | 営業担当 |
| C | 無料ヒアリング日時 |
| D | 確認できた課題 |
| E | 提案する1業務 |
| F | 提案金額 |
| G | 案件状況 |
| H | 技術担当 |
| I | 受注日 |
| J | 納品予定日 |
| K | 次のアクション |
| L | メモ |
| M | 提案商談日時 |

提案準備開始時は、対応する行が存在する場合に限り、確認済み内容でD〜H、K、Mを更新できる。提案商談用PDFが完成したらGを `提案商談予定` にできる。

URL専用列は2026-08-28時点で存在しない。勝手に列を追加せず、Drive URLは完了報告で返す。将来URL列が追加された場合は、列名と対象行を読み直してから記入する。
