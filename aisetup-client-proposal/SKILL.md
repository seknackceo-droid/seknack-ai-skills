# AIセットアップ会社別提案書

```yaml
created_at: 2026-08-28
owner: @営業顧客責任者
business: AIセットアップ事業
purpose: 初回無料ヒアリングの内容から、会社別の提案・見積・商談用PDF・Drive URLまで一貫して作る
target: SeKnAck営業担当、技術担当、最終承認者
source:
  - AIセットアップ事業_営業導入管理_2026-08-28
  - AIセットアップ事業_初回ヒアリングカルテ_原本
  - ユーザー確定のサービス条件
status: review
next_action: 最初の実案件で前半ページと共通ページを校正し、承認済み基準画像を追加する
main_owner: @営業顧客責任者
reviewers:
  - @制作納品責任者
  - @品質法務責任者
qa_required: true
human_approval_required: true
```

## 成果

営業担当はこのスキルを1つ起動し、会社ごとに複製した初回ヒアリングカルテのURLを渡す。スキルは次を一続きで行う。

1. カルテを読み、事実・顧客発言・営業仮説・未確認事項を分ける
2. 不足情報をまとめて質問し、提案する1業務を壁打ちする
3. 標準範囲か追加見積候補かを判定する
4. 技術確認と金額承認を得て見積内容を固定する
5. 前半の会社別ページと後半の共通ページを設計する
6. SeKnAckブランドで1ページ1画像を直列生成する
7. PDF化・検品し、最終承認後にGoogle Driveへ保存する
8. Drive URLと次のアクションを返し、利用可能なら案件管理表へ反映する

## 統合済みの資料制作機能

このスキルは、`dododo-siryou` のうち会社別営業提案に必要な工程を内部契約として統合している。利用者が別途 `dododo-siryou` を起動する必要はない。

- 目的・読者・利用場面・最終判断の確認
- ヒアリング内容と全ページ主張の逆引き
- 意思決定ブリーフと営業提案向けの物語設計
- 全ページ構成・見出し台本・前後接続の一括承認
- STYLE DNAと固定部品契約
- 表紙、本編標準、CTA標準の三点校正
- 1ページ1画像の直列生成と5秒理解テスト
- ページ画像、PDF、公開メタデータの検品

汎用資料の制作形式を毎回選ばせず、この用途では `full_deck`、文字入り完成画像、16:9、PDF、商談で説明した後に顧客へ送付する資料を既定とする。ユーザーが今回別形式を明示した場合だけ変更する。

## 必ず読む参照

- 起動時に [references/hearing-and-walling.md](references/hearing-and-walling.md) を読む。
- 提案範囲や金額を扱う前に [references/service-terms.md](references/service-terms.md) を読む。
- 構成作成と画像生成の前に [references/deck-production-contract.md](references/deck-production-contract.md) を読む。
- PDF化、Drive保存、管理表更新の前に [references/handoff-and-qa.md](references/handoff-and-qa.md) を読む。

参照を読まずに、価格、対応範囲、ページ構成、公開設定を決めない。

## 起動入力

推奨する開始文は次の形とする。

```text
$aisetup-client-proposal
ヒアリングシート: https://docs.google.com/spreadsheets/d/...
```

URLがない場合だけ、会社ごとに複製した初回ヒアリングカルテのURLを求める。原本そのものへ顧客情報を書き込まない。

## ライブ正本

次の順で確認し、古いローカル資料より優先する。

1. ユーザーが今回指定した条件
2. ヒアリングカルテの記入内容
3. `AIセットアップ事業_営業導入管理_2026-08-28` の `99_設定`
4. 同シートの `02_案件管理` と `04_情報保管庫`
5. このスキルの `references/service-terms.md` にある確認済みスナップショット

ライブ正本とスナップショットが食い違う場合は、ライブ正本を採用し、差分を人間へ示す。過去の商談資料や旧価格表を価格・保守条件の根拠にしない。

## 標準ワークフロー

### 1. 接続と対象確認

- Google Sheetsを読めるか確認する。
- 画像生成機能を使えるか確認する。
- PDFを作れる環境か確認する。
- Google Driveへ保存できるか確認する。
- 対象URLが `AIセットアップ事業_初回ヒアリングカルテ_原本` そのものなら、顧客情報の記入や提案生成を止め、会社別コピーを求める。

Drive連携がない場合も、ローカルPDF完成までは進める。Drive URLを作ったふりはしない。

### 2. カルテ読取と提案ブリーフ

[references/hearing-and-walling.md](references/hearing-and-walling.md) の項目へマッピングし、次の4区分で表示する。

- 確認済み事実
- 顧客が話した希望・評価
- SeKnAck側の提案仮説
- 技術・金額・権限の未確認事項

資料の公開区分は原則 `機密・当該顧客共有` とする。会社名、担当者名、業務内容を画像生成へ渡してよいかを確認し、不要な連絡先、アカウント情報、個人情報は入れない。

空欄を機械的に全部聞かない。提案する1業務、入出力、人間確認、例外、実行環境、見積もりに影響する不足だけを質問する。

### 3. 壁打ち

- 1問ずつ小刻みに聞かず、関連する5〜8問を1回にまとめる。
- 各質問へ「なぜ必要か」と推奨仮置きを短く添える。
- 原則2ラウンド以内で、提案候補の1業務と現在・導入後フローを固める。
- 顧客が言っていない課題、時間削減、売上効果、件数を創作しない。
- 成果は保証せず、「可能になる作業」「想定する運用」「確認方法」で表現する。

### 4. 標準範囲と追加見積候補

[references/service-terms.md](references/service-terms.md) の判定を使う。

- 標準範囲なら、ライブ設定の先行導入価格を見積案に使える。
- 複雑性シグナルがある場合は、追加理由と確認事項を整理する。
- 追加金額は、承認済み価格表または技術担当・最終承認者の明示金額がある場合だけ記載する。
- AIが独自に追加料金や納期を決めない。

### 5. 見積承認ゲート

提案画像を作る前に、チャットで次を一度に提示する。

```text
提案する1業務:
対応範囲:
対象外:
顧客が用意するもの:
見積金額（税別）:
月額プラン:
想定納期:
技術確認者・確認日:
未確認事項:
```

金額・対応範囲・納期に人間の明示承認がない間は、`見積案 / 要確認` とする。顧客提出用PDFへ確定値として焼き込まない。

### 6. 二段構成の提案書

- 前半は会社ごとに変える。
- 後半は共通条件を使うが、ライブ正本との一致を毎回確認する。
- 全体は通常10〜14ページとし、内容に応じて増減できる。
- 問い合わせ用の活用事例集を混ぜない。必要な事例がある場合だけ1ページ以内で個別提案の理解補助として使う。

構成、表示文、見積内容をまとめて提示し、ユーザーの構成承認を得る。承認前に画像生成しない。

### 7. 画像生成

[references/deck-production-contract.md](references/deck-production-contract.md) を守る。

- 制作方式は文字入り完成画像。
- 16:9、1ページにつき独立したラスター画像1枚。
- SeKnAck公式ロゴと固定ブランド色を使う。
- SVG、HTML、Canvas、ネイティブ図形をスライド画像の既定制作経路にしない。
- 1回につき1ページだけ生成し、ページ順に直列で進める。
- 指定した日本語以外を追加させない。
- 初回またはデザイン変更時は、表紙、本編標準、見積・CTA標準を順番に校正し、承認後に残りを生成する。
- 承認済みの基準画像と固定部品がある場合は再校正を省略できる。ただし会社名、金額、範囲、日付は毎回原寸確認する。

### 8. PDF・QA

- ページ画像を連番PNGで保存する。
- `scripts/build_proposal_pdf.py` でPDFとmanifestを作る。
- ページ数、順序、16:9、重複、文字、金額、会社名、メタデータを確認する。
- PDFをPNGへ再レンダリングし、全ページを原寸で確認する。
- 顧客へ渡す前に、人間の最終承認を得る。

### 9. Drive保存

- 顧客別のGoogle Driveフォルダへ最終PDFを保存する。
- 保存先が不明なら、既存の顧客案件フォルダを検索する。見つからない場合は勝手に公開フォルダへ置かず、保存先を確認する。
- 最終承認前は制限付き共有を既定にする。
- 「リンクを知っている全員が閲覧可」への変更は、ユーザーがその共有範囲を承認した場合だけ行う。
- アップロード後、実際のDrive URLと共有権限を読み戻す。

### 10. 案件管理

- `02_案件管理` に同じ会社の行がある場合、確認済みの提案する1業務、提案金額、案件状況、次のアクションを更新できる。
- 提案URL専用列が存在する場合だけURLを記入する。
- 専用列がない場合、既存列を勝手に増やしたり、メモへURLを押し込んだりしない。Drive URLを完了報告で返す。
- 顧客別提案書を `04_情報保管庫` の共通資料として登録しない。

## 承認の意味

- 内容承認: 提案する業務、フロー、範囲の承認
- 見積承認: 金額、支払い、納期、追加費用条件の承認
- デザイン承認: 新しいページ種別や基準画像の承認
- 外部共有承認: 顧客へ渡せる共有範囲にする承認

一つの承認を別の承認として流用しない。沈黙や別件への返答を承認とみなさない。

## 停止条件

- ヒアリングカルテが原本、空欄、または別会社の情報を含む
- 提案する1業務を特定できない
- 技術確認なしで複雑案件の実現可否・追加金額・納期を断定する必要がある
- 顧客情報を共有スキル、公開GitHub、共通資料へ保存しようとしている
- 画像生成、PDF化、Drive保存の実行環境がなく、利用できるふりをすることになる
- 同じ画像不具合が2回続き、文字量や構成を減らしても解消しない

停止しても、確認済みの提案ブリーフ、未確認事項、次の担当者まで残す。

## 完了条件

- ヒアリング内容と提案内容を逆引きできる
- 見積・納期・範囲に承認記録がある
- 前半と後半の内容が矛盾していない
- PDFを全ページ確認済み
- Google Drive URLと共有権限を実地確認済み
- 案件管理へ反映した項目を読み戻し済み
- 顧客情報がスキル本体や共通GitHubへ残っていない
- 完了報告に、PDF、Drive URL、金額、ページ数、共有範囲、未確認事項を示した
