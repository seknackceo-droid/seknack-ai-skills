# 営業リスト登録契約

## 正本列

| 列 | 項目 | 登録ルール |
|---|---|---|
| A | 登録日 | 実際の登録日 |
| B | 会社名・店舗名 | 公式表記 |
| C | 業種 | 既存の選択肢に合わせる |
| D | エリア | 市区町村を含める |
| E | 公式サイトURL | 公式サイト |
| F | 問い合わせフォームURL | 直接開けるフォームURL |
| G | 送信用文面 | `04_情報保管庫` の承認済み業種別テンプレートを基にし、外部閲覧可能な `AIエージェント活用イメージ30選` のURLをCTA前へ入れる |
| H | 送信担当 | `99_設定` の有効な担当者。現状は上村 |
| I | 送信状況 | `未対応` |
| J | 送信日 | 空欄 |
| K | 反響状況 | `なし` |
| L | メモ | 選定根拠を短く記録 |
| M | 営業担当 | `99_設定` の有効な担当者。現状は上村 |
| N | 送信文（署名込） | 数式列のため書き込まない |
| O | 承認状況 | `承認待ち` |
| P | 送信キュー | 数式列のため書き込まない |
| Q | 除外・処理メモ | 通常は空欄 |

## 登録禁止

- `営業可否` 列を新設しない
- `承認OK` をAIが設定しない
- N列とP列の数式を上書きしない
- フォームが送信可能か確認できない企業を仮登録しない
- 個人メールアドレスを推測しない

## スキル切り替え契約

- リサーチスキルはO列を `承認待ち` にして終了する
- 人間だけがO列を `承認OK` に変更する
- P列は数式結果が `送信待ち` になったことを読み取るだけで、直接書き込まない
- O列が `承認OK`、P列が `送信待ち` になった行は `$aisetup-inquiry-form-send` の対象になる
- リサーチ依頼だけの場合は送信スキルへ自動移行しない。利用者からフォーム処理の依頼がある場合だけ切り替える
