# 安全な初期質問

質問は1問ずつ行う。回答しにくい項目は「要確認」または仮名で進められる。

## 最初の注意

次の実体は聞かない。

- 個人名、顧客名、仕入先名、従業員情報
- 電話、メール、住所、口座、給与、契約条件
- パスワード、APIキー、二要素コード、セッション情報
- 社内資料の本文、実際の売上、人事評価、営業秘密

## 質問順

1. 「授業用の架空会社」と「実際の会社向け（非公開の下書き）」のどちらですか。推奨は先に架空会社で練習すること。
2. フォルダに使う架空会社コードは何ですか。授業用は実名を禁止し、利用者が入力した短い名前を英大文字と数字だけのコードへ整えて `研修会社-SAMPLE` のようにする。日本語の社名らしい文字列は受け付けない。実際の会社か不明なら、実際の会社向けの停止条件を適用する。
3. 業種は「サービス業 / 小売業 / 建設・施工業 / 製造業 / 医療・福祉 / 士業 / 不動産業 / IT業 / その他」から選んでもらう。内部IDはAIが変換し、利用者へ見せない。
4. 規模は「1〜10名 / 11〜50名 / 51〜200名 / 201名以上」から選んでもらう。
5. 利用するAIはCodexだけですか。この版はCodexのみ生成する。
6. 部署ごとに「作る / ほかの部署にまとめる / 作らない / あとで確認」で分ける。「ほかの部署にまとめる」はまとめ先も日本語の部署名で聞く。実企業は全13機能の確認が必須。
7. AIに任せたい作業は、読み取り/整理/下書き/比較/分析/社内更新候補のどれですか。
8. AIに任せない作業は、外部送信/公開/契約/金額/支払い/採用判断/削除/本番変更のどれですか。推奨は初期はすべて人間承認。
9. 扱う可能性がある情報区分の「有無」は何ですか。公開情報 / 社内情報 / 顧客の機密情報 / 個人情報 / 人事・労務情報 / 契約・法務情報 / 支払い情報 / パスワード等の認証情報から有無だけを聞く。
10. 外部AIへ社内情報を入力できる社内承認はありますか。不明なら「非公開情報は入力禁止」とする。
11. 最後に確認する人の役割は「代表者 / 部門責任者 / 情報管理責任者 / 導入責任者 / 授業の進行役」のどれですか。個人名や自由記述は受け取らない。
12. 生成先は端末内のアクセス制限されたローカルフォルダですか。macOS/Linuxは `Documents/AI導入研修`、Windowsは `%USERPROFILE%\Documents\AI導入研修` が基本候補。WindowsのDocumentsがOneDrive配下なら同期フォルダとして扱う。公開リポジトリ、Skillフォルダ、共有テンプレート、同期フォルダは不可。クラウド保存は利用者が明示し、共有範囲を確認した場合だけ専用確認を付ける。Windowsでは「プロパティ → セキュリティ」の確認も必須。
13. 既存フォルダはありますか。ある場合は上書きせず、差分提案で止める。

## JSON設定例

会社固有の回答は公開Skill配下へ保存しない。

```json
{
  "company_display_name": "研修会社-SAMPLE",
  "mode": "training",
  "industry_id": "service",
  "company_size": "11-50",
  "platform": "codex",
  "profile": "standard",
  "human_approver_role_id": "training_facilitator",
  "sensitive_categories": ["personal", "customer_confidential"],
  "external_ai_internal_data_allowed": false
}
```

利用者には日本語だけを見せる。設定JSONを作るAIは、授業用を内部値 `training`、実際の会社向け（非公開の下書き）を `real-draft` に変換する。授業用は `profile` から自動生成できる。実際の会社向けは `profile` を使わず、全カタログIDを `department_statuses` に指定する。

```json
"department_statuses": {
  "strategy": {"status": "active"},
  "general_hr": {"status": "combined", "combined_with": "strategy"},
  "finance": {"status": "uncertain"},
  "sales": {"status": "unused"}
}
```

内部では「作る」=`active`、「ほかの部署にまとめる」=`combined`、「作らない」=`unused`、「あとで確認」=`uncertain` とする。`it`, `security_legal`, `quality` は必ず `active` にする。実際のJSONでは上記4件だけでなく、全13件を指定する。POSIX環境では生成前に設定JSONをモード `600` にする。
