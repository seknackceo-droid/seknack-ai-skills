# 部署カタログと選定

ここでの部署はAIの機能分担であり、人事上の正式組織を確定しない。小規模企業では兼務でよい。

## 統制層

`00_会社統括` は常に作る。その配下に、次の3機能を必ず含める。

- IT・AI管理。アカウント、権限、外部連携、端末、バックアップ候補の確認。
- 安全・法務。個人情報、機密、契約、公開、事故対応の確認。
- 品質確認。範囲、根拠、未確認、承認記録、差し戻し。

## 業務機能

- 経営企画。方針、優先順位、目標指標の候補、部署間調整。
- `general_hr`: 総務人事。社内文書、人事採用の下書き、教育、労務の要確認整理。
- `finance`: 経理財務。請求・見積・支払いの下書きと照合候補。確定・支払いは人間。
- `sales`: 営業。候補整理、商談メモ、提案下書き。送信・価格確定は人間。
- `marketing`: マーケティング広報。調査、企画、原稿、画像候補。公開は人間。
- `customer_success`: 顧客対応。問い合わせ整理、返信下書き、次アクション。返信・補償約束は人間。
- 商品・サービス企画。要望整理、仕様案、価値仮説、テスト条件。
- 現場業務。作業手順書の下書き、日報、点検、例外整理。安全判断・顧客提出は人間。
- 仕入れ・発注。比較表、発注候補、仕入れ条件の整理。発注・契約は人間。
- `rnd`: 研究開発。技術調査、実験計画、結果整理。実験実行と安全判断は別承認。

## プロファイル

- 基本構成: 経営企画、総務人事、経理財務、営業、現場業務、IT・AI管理、安全・法務、品質確認
- 標準構成: 基本構成 + マーケティング広報、顧客対応、商品・サービス企画
- 全部署構成: 標準構成 + 仕入れ・発注、研究開発

利用者には「基本構成 / 標準構成 / 全部署構成」と表示する。内部IDはそれぞれ `minimal` / `standard` / `extended` とする。授業用だけ構成を一括選択できる。実際の会社向けは全13機能を「作る / ほかの部署にまとめる / 作らない / あとで確認」に分ける。「ほかの部署にまとめる」は独立フォルダを作らず、指定部署へ引き継ぐ。IT・AI管理、安全・法務、品質確認は必ず独立して作る。

## 保留

存在、名称、責任範囲、人間承認者が未確定の機能は、`99_未確定/README.md` の候補へ入れ、部署 `AGENTS.md` を有効化しない。
