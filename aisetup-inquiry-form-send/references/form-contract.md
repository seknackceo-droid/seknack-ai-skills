# フォーム入力契約

## 営業リスト

| 列 | 項目 | 用途 |
|---|---|---|
| F | 問い合わせフォームURL | 開くフォーム |
| H | 送信担当 | 送信者マスタの検索キー |
| I | 送信状況 | 完了後のみ更新 |
| J | 送信日 | 完了後のみ更新 |
| N | 送信文（署名込） | 本文へ入力 |
| O | 承認状況 | `承認OK` のみ処理 |
| P | 送信キュー | `送信待ち` のみ処理 |
| Q | 除外・処理メモ | エラー、確認事項、結果を記録 |

## 送信者マスタ

`99_設定` のK列からW列を、H列の送信担当名で検索する。K列は検索用キー、W列はフォーム入力用の氏名として分ける。

| 列 | 項目 | 標準的なフォーム表示 |
|---|---|---|
| K | 営業担当キー | 営業リストとの照合用。フォームには入力しない |
| L | 電話番号 | 電話、TEL |
| M | 共通メール | メール、E-mail |
| N | 署名 | 本文にはN列の送信文を優先 |
| O | 会社名 | 会社名、法人名 |
| P | 部署名 | 部署、所属 |
| Q | 役職 | 役職 |
| R | 氏名カナ | フリガナ、氏名カナ |
| S | 郵便番号 | 郵便番号、〒 |
| T | 住所 | 住所、所在地 |
| U | 会社URL | URL、Webサイト |
| V | 利用状態 | `有効` の担当者だけ使用 |
| W | フォーム入力氏名 | 氏名、担当者名、お名前 |

## 追加項目DB

標準マスタに列がない項目は、`99_設定` のX列からAC列へ1項目1行で保存する。営業担当キーと項目名と適用範囲の組み合わせが同じ行を重複登録しない。

| 列 | 項目 | 用途 |
|---|---|---|
| X | 営業担当キー | K列と同じ検索キー |
| Y | フォーム項目名 | 表示ラベルを正規化した名称 |
| Z | 入力値 | 次回以降に再利用する値 |
| AA | 適用範囲 | `共通` または対象ドメイン |
| AB | 確認日 | 利用者から確認した日 |
| AC | 補足 | 入力条件、表記制約、確認元 |

標準項目の回答はK:Wの既存担当者行へ保存し、追加項目DBへ重複させない。追加項目を使う前は、営業担当キーと適用範囲の両方を照合する。

## 入力原則

- 表示ラベルを最優先し、name属性、placeholderを補助にする
- 氏名欄にはW列、氏名カナ欄にはR列を使い、K列の営業担当キーで代用しない
- 姓名が分割されていて分割根拠がない場合は推測せず止める
- 電話番号や郵便番号のハイフン要否は入力欄の制約に合わせる
- 未登録の必須項目は推測せず、利用者へ確認してシートへ保存した後に同じフォームを再開する
- 確認画面がある場合も、最終確定ボタンは人間に残す
- 送信完了表示が出るまでスプレッドシートを送信済みにしない

## 10タブバッチと結果記録

- 対象行は最大10件ずつGoogle Chromeのタブで開く。残数が10件未満なら残数だけを開く
- 1バッチの入力完了後は送信結果を待たず、次の最大10件を開いて入力し、承認済み対象が尽きるまで続ける
- シート行番号、会社名、フォームURL、タブ識別子を対応付け、タブ順だけで行を判断しない
- 入力完了後にChromeを前面へ出し、人間が各タブの同意、CAPTCHA、確認画面、最終送信を処理する
- 利用者の `送信完了` は結果確認開始の合図であり、バッチ全件の成功証明ではない
- 明確な完了文言または完了通知を各タブで確認できた行だけ、I列とJ列を更新する
- 更新後は対象行のI:Qを読み戻し、別行を更新していないことを確認する
- 確認画面、元フォーム、入力エラー、同意未完了、CAPTCHA、通信エラーは未完了として扱う
- 機械確認できない場合はI列を送信済みにせず、Q列へ `要確認: 送信完了画面未確認` と記録する
- 利用者が会社名を指定して成功を明示した場合だけ、人間確認としてその行を更新し、Q列へ `送信完了（人間確認）` と記録する
